## 3. Technical design

### 3.1 Architecture

The system is composed of:

- **Input layer.** Accepts <<DATA_CATEGORIES>>.
- **Model layer.** Calls <<MODELS>>.
- **Output layer.** Produces structured output consumed by <<USERS_AFFECTED>>.
- **Control layer.** Rate limiting, input validation, audit logging.

### 3.2 Data flow

1. Input is received from the user interface or an upstream service.
2. Input is validated against a schema; unrecognised keys are rejected.
3. Validated input is delimited and passed to the model with a fixed system prompt.
4. The model response is parsed against an output schema. A response that fails
   validation is retried once and then rejected.
5. Validated output is written to the application database within a transaction.
