## 1. Principle

Article 14 requires oversight to be **effective**, not nominal. Two tests decide
whether a control is real:

1. **Can a human actually stop it?** A control that only advises is not
   oversight. The system must be technically interruptible by a person who has
   the authority and the means to do so.
2. **Can a human understand it?** A person must be able to form a reasoned
   judgement about whether the output is acceptable, which requires enough
   context and enough time.

## 5. Interruption mechanisms

The following controls allow a person to stop the system acting:

- A feature flag disables all model calls; the application returns an explicit
  unavailable response rather than a degraded or guessed one.
- A per-user block prevents a specific account from causing further model calls.
- A provider-level circuit breaker stops calls when the error rate crosses the
  threshold, so a runaway loop cannot continue while a human is deciding what
  to do.

Each is covered by an acceptance test. A control that is not tested is a claim,
not a control.

## 6. Automation bias

The most common failure of human oversight is that people approve generated
output because it looks plausible. Two mitigations:

- **Friction proportional to consequence.** Actions with a higher consequence
  require a slower, more explicit confirmation.
- **Confidence is not shown as if it were truth.** The interface distinguishes
  what the model retrieved from what it generated, so a reviewer is not reading
  fluent prose as if it were a citation.
